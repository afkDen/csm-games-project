# Impeccable Policy — Audit / Polish Boundary

Impeccable is optional and should be used after the project's identity and route grammar already exist.

## Good uses

- hierarchy/readability critique
- responsive fit
- control clarity
- accidental AI-template patterns
- typography/spacing polish
- obvious accessibility problems
- interface/HUD quality

## Boundary

Do not let a generic audit rewrite the core identity, remove the lens metaphor, flatten spatial layouts, or replace bespoke character-world composition with safer standard sections.

If live/hook tooling is blocked or cannot be trusted in the environment, record the blocker rather than bypassing it.

## Usage log rule

If used, evidence must include:

`boundary=preserved`

and identify specific findings/fixes rather than claiming a blanket clean pass.
