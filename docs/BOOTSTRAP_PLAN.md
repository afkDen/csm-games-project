# Bootstrap and Delivery Plan

Every task is first classified by `docs/PROCESS_TIER_POLICY.md`. Major/architectural milestones use the audited loop in `docs/AGENT_LOOP_PROTOCOL.md`:

`experience-orchestrator → orchestration-auditor → production-implementer → implementation-reviewer → closeout`.

The first-slice preproduction phase stops after the audited plan until owner approval; later phases continue automatically unless the owner holds the project.

## Phase 0 — autonomous bootstrap

- inspect owner inputs and credential configuration without exposing secrets;
- validate the portable core, active runtime adapter, and project-local skills;
- verify project-local skills; install external skills only from reviewed revisions / explicit trust opt-in; verify browser tooling and current-doc context where possible;
- update capability registry from actual runtime availability;
- establish minimum app/toolchain foundation only when needed;
- confirm provenance/secrets boundaries and run validators;
- do not build character routes yet.

Gate: bootstrap healthy enough to plan the first slice, or a true owner-only blocker is isolated and recorded.

## Phase 1 — audited first-slice preproduction

1. Controller creates the first milestone run folder.
2. Orchestrator produces still-aesthetic profile, character-fidelity translation, pastel tonal plan, fifteen-axis world signature, 0–100 experience score, spatial-depth plan, route-owned transition grammar, interruption/retarget model, signature interaction, engineered peak, lens storyboard, asset-gap map, FFmpeg/media derivative plan when a beat needs it, minigame spec, audio palette, mobile strategy, experience-first quality plan, risky proofs, capability routing, reasoning-routing decision, and reviewer contract.
3. Orchestration auditor independently uses applicable skills/MCPs to improve and challenge the plan.
4. `REVISE` loops back up to three rounds.
5. `APPROVED FOR IMPLEMENTATION` sets project state to `AWAITING_FIRST_SLICE_APPROVAL`.

Do not implement the major slice before the owner's production green light.

## Production green light

When the owner clearly says **“Approved. Proceed.”**, activate `PRODUCTION_AUTOPILOT.md` and switch mode to `AUTOPILOT`. This is the main production approval; do not invent routine owner gates afterward.

## Phase 2 — risky technical proofs

Run audited milestones for the first-slice risks:

- lens masking/refraction + ownership transition;
- still-to-cinematic depth treatment + representative scroll-scrub choreography;
- at least two plausible chibi representation strategies before locking the first game pipeline;
- intended-complexity game loop;
- audio unlock/ambience/SFX/pause/visibility + measurable verification;
- persistent Canvas/route transition architecture.

Gate: proofs pass real browser/reviewer evidence. Failed proofs repair or return to orchestration.

## Phase 3 — complete first vertical slice

Build and independently review:

`pastel hub → enter lens → still-led spatial scroll score → signature interaction → engineered peak → frame/product beat → portal → minigame → result → return → updated hub`.

Gate: still/pastel/character fidelity, full forward/back scroll, dead-scroll check, spatial depth, signature interaction, peak, desktop/mobile, route recovery, full game loop, audio, reduced/adaptive-quality behavior, performance floor, and representative intermediate states pass review.

## Phase 4 — shared-mechanism extraction

Orchestrator identifies only abstractions proven by the integrated first slice. Auditor specifically checks that extraction does not flatten authored world structure. Reviewer verifies no first-slice regression.

Shared candidates: renderer lifecycle, portal primitives, global input/pause/visibility, audio buses, progression, quality tiers, game lifecycle shell, preload/disposal, accessibility/recovery.

Do not abstract still interpretation, route composition, scroll score, camera grammar, signature interaction, depth plan, typography staging, game mechanics, character sound palette, mobile translation, or dramatic portal staging.

## Phase 5 — remaining worlds one at a time

For each unbuilt character:

1. orchestrate distinct world + game signature and capability routing;
2. audit against all existing worlds using active creative-direction/scroll/depth/still/asset/game/audio skills;
3. implement only approved world-specific and shared needs;
4. review cinematic intermediate states, game loop, audio, mobile and uniqueness;
5. run shared-system regressions;
6. close and continue automatically.

No routine owner approval between worlds.

## Phase 6 — whole-experience integration

Use the loop for progression/orderings, deep links/history, hub transformation, all-worlds-complete payoff, route contrast, audio ownership, memory cleanup, mobile continuity, and recovery.

## Phase 7 — hardening

Use the loop for Playwright/browser journeys, screenshot/gameplay review, performance/GPU investigation, Lighthouse/MotionScore when available, interface/accessibility audit, bounded late-stage Emil/Impeccable when materially useful, security/secrets review, and provenance finalization.

## Phase 8 — release review

Follow `FINAL_RELEASE_GATE.md`. Final completion requires reviewed multi-agent evidence, not only a passing build.
