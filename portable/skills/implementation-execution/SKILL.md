# Implementation Execution

The approved `ORCHESTRATION_PACKET.md`, `CAPABILITY_ROUTING.md`, and `ORCHESTRATION_AUDIT.md` are the milestone contract.

## Rules

1. Implement the approved user-visible goal; do not redesign the product because a different implementation is easier.
2. Invoke each `REQUIRED` capability at the assigned point and preserve useful outputs/evidence.
3. Activate `CONDITIONAL` capabilities only when their trigger occurs; record whether the trigger fired.
4. Never claim a capability as used solely because its instructions were read.
5. Keep owner source assets in `assets/source/`; create intentional derivatives under `public/assets/derived/` only when needed.
6. Respect the still-led pastel creative hierarchy, world-uniqueness contract, scroll score, route-owned transition grammar, signature interaction, spatial-depth plan, and shared-mechanism boundaries.
7. Do not replace approved scrubbed/spatial choreography with generic fade/slide reveals or flat substitutes because they are cheaper to code.
8. When performance is insufficient, follow `docs/PERFORMANCE_AND_QUALITY.md`: optimize assets/inactive work/secondary effects before primary creative systems.
9. Reopen `asset-scout` when an approved beat has a concrete material gap instead of improvising a weak generic substitute.
10. Keep high-frequency simulation state in an appropriate runtime owner rather than broad UI render state.
11. Build deterministic/debuggable seams for games and audio where practical.
12. Verify forward/back scroll, representative 25/50/75% direction flips, eligible mid-transition control activation, duplicate activation, and intermediate states locally as implementation proceeds; do not save every check for the reviewer.
13. Use `media-pipeline-ffmpeg` when a routed media transformation need exists and FFmpeg is available; preserve reproducible derivatives rather than hand-waving media preparation.
14. If implementation discovers a material contradiction in architecture, rights, world identity, or approved experience, stop that affected branch and escalate to the orchestrator instead of silently changing direction.

## Evidence handoff

Write `IMPLEMENTATION_REPORT.md` with:

- files/areas changed;
- capabilities actually used and how they affected the result;
- conditional capabilities whose triggers did/did not fire;
- tests/browser checks performed;
- known limits or unresolved questions;
- exact states the reviewer should inspect.

The implementer does not mark the milestone complete.
